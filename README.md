# 海南大学网球定场 V4.1 · Tennis Everyday

> **V4.0 的主题是「急速抢单」：把 8:00 放号那一刻的第一发请求做到最快。**
> 上一版赢在功能多，这一版赢在**快**。
> **V4.1 的主题是「挂机过夜」**：晚上挂这儿，第二天早上 8:00 自己刷 token、自己抢场。
> 见下方 [V4.1 新增](#v41-新增挂机过夜开抢前自动刷新-token)。

## ⚡ V4.0 更新了什么

学校每天 **8:00** 放号，能不能抢到就看第一发请求什么时候到服务器。这版围绕这件事做了四件事：

### 1. 自动校正服务器时钟差（本版最大收益）
程序会主动问服务器「现在几点」，算出**你电脑和学校服务器差多少**，然后把开抢时刻提前/推后相应的量。

实测同一台机器能差 **1.56 秒** —— 也就是说，按本机 8:00:00 发出时，服务器那边已经是 8:00:01.5 了，
**等于白送别人一秒半**。现在这个差值会被自动补偿掉。

> 原理：读 HTTP 响应头里的 `Date`（服务器时间），和本机时间比。
> `Date` 只有秒精度且向下截断，所以取多次采样的最大值再补 `1/(n+1)` 秒来消除这个系统偏差。
> 差值超过 10 秒视为测量异常，宁可不校正。

### 2. 开抢前 2 秒预热连接
新建 HTTPS 连接要一次完整的 TCP + TLS 握手，实测 **128~135 ms**。
程序在放号前 2 秒先发一次只读查询把连接捂热，这 130ms 就不用算在第一枪头上了。

### 3. 毫秒级倒计时
- 最后 1 秒：睡眠粒度 5 毫秒
- 最后 80 毫秒：直接盯着时钟忙等
- 到点瞬间把节流清零，第一发不会被之前的请求拖住

实测**第一枪相对目标时刻延迟 0 毫秒**。

### 4. 速率参数按实测定死
| 参数 | 值 | 依据 |
|---|---|---|
| 最小间隔 | `0.15s`（≈6.7 次/秒） | 服务端限流门槛在 9 次/秒附近（连打 8 次被拒 6 次），要留余量 |
| 抖动 | `0` | 要的是最快，不是错峰 |
| 连发次数 | `2` | 同一候选补一枪，成功立即熔断 |
| 侦察线程 | `14` | 只读接口，14 并发实测 29.3 次/秒，全量空场图 0.48 秒 |
| 周期刷新 | `0` | 抢购头几秒最金贵，不在候选之间停下来重新侦察 |

另外：被限流时会**自适应放宽**节流（`min_interval × 1.5`，上限 0.6s），而不是硬睡 1.8 秒。

### 串行 vs 并行：实测数据（`平行首发` 默认关闭）

既然一天只能成交一单，能不能几个场地同时发？实测了三组（安全参数，不会成单）：

| 方式 | 限流 | RTT 中位 |
|---|---|---|
| 同一场地连打 8 次（无间隔） | **7 发全被限流** | 104ms |
| 7 片场地**并行**同时发 | 0 | **243ms**（最慢 351ms） |
| 7 片场地**串行** @150ms | 0 | 143ms |

两个结论：
1. **并发不同场地不触发限流**，但服务端要排队，每个请求的往返会从 ~143ms 涨到 ~243ms；
2. **真正会挨限流的是"同一个目标连打"** —— 第 2 发就被拒，之后持续被拒。

所以并行的价值**不在于更快，而在于更广**：一次覆盖多个候选，不用等前一个失败了再试下一个。

配置里的 `parallel_first`：

- `0`（默认）：纯串行，一个一个试。第一发的结果回来最快，最稳。
- `2~3`：抢单第一轮同时打前 N 个候选，谁先有就是谁；之后自动转回串行。

⚠️ **开并发的注意**：理论上存在"其中两发同时成交"的窗口（服务端的「每天一单」检查有竞态）。
实测里没出现过，但抢完请到「我的订单」核对一眼，多出来的需要手动退掉。

### 防无限重试

如果候选一直被服务端回「已被占用」而侦察数据又没变化（缓存/抖动），
原逻辑会一轮一轮无限试下去。现在最多全量重试 **6 轮**就停，避免空耗。

### 其它修复
- 🔄 **重新获取 token** 会排除掉浏览器档案里残留的旧 token（否则"重取"回来的还是那个失效的）；
  如果 CAS 免验证放行导致没换发新 token，日志和弹窗会明确告诉你「请清除设备信任再登录」。
- 浏览器登录**自动填学号密码并自动提交**（CAS 的登录按钮事件只绑在另一个表单上，
  直接点 `#pwdFromId` 的按钮是没反应的，改为走页面自己的加密函数 + 原生提交）。
- 开抢前若侦察到「还没放号」，会**等到放号那一刻**再抢（原来会直接退出，永远等不到 8:00）。
- 下午点「8:00 自动抢」会自动顺延到**第二天早上**（原来会判定时间已过而立即开打）。

## V4.1 新增：挂机过夜（开抢前自动刷新 token）

**场景**：晚上把电脑挂在这儿，第二天早上 8:00 它自己刷新好 token、自己把场抢了。

**为什么需要刷新**：token 是服务端会话凭据，实测寿命不到 10 小时。
晚上 23 点挂机到早上 8 点，隔了 9 小时，旧 token 必然已经 401。

**为什么必须记住密码**：实测过「信任此设备」的会话同样会过期 ——
隔几小时后免密刷新会直接落到扫码页，拿不到 token。所以无人值守刷新
只能靠**重新登录一次**，这就必须在本机记住密码。

**完整时序**（以 8:00 开抢、提前 15 分钟为例）：

```
22:00  你点「⏰ 8:00 自动抢」→ 程序开始挂机等待
07:45  自动逐个账号重新登录 → 换新 token → 校验 → 写回配置
       同时把目标日期滚到「今天 + 2 天」（跨天挂机必做，否则超出预约窗口）
07:45~ 若这一步要手机确认多因子认证，浏览器会停在那儿等你，最久等到 08:00
08:00  所有账号按各自的时间窗口并行开抢
```

**怎么开**：
1. 账号表里点某一行的 **🔑** → 填一次密码（只存本机 `config.json`，且做了混淆；
   `config.json` 已在 `.gitignore` 里，永远不会进仓库）。
2. 「**挂机过夜**」卡片里确认开关是开的、提前分钟数（默认 15）。
3. 睡前点一次 **🔑 立即刷新 token**，确认日志里是 `✓ … token 已刷新`。

**密码存哪、安不安全**：`config.json` 里形如 `v1:GBZEHg0…`，是**混淆不是加密**
—— 目的是不让明文一眼可见（截图、误传时不直接泄露），挡不住真想解的人。
不想要了就删掉，或在账号行点 🔑 留空确定即可清除。

## 二、账号库怎么用

### 1. 登录第一个账号
左侧「**Token 自动获取**」→ **方式一**：填学号 + 门户密码 → 点 **🔑 登录并获取 token**。

登录成功后，上方「**凭证与目标 · 账号库**」表里就多了一行：

| 账号 | 学号 | 用户ID | Bearer Token | 状态 | 操作 |
|------|------|--------|--------------|------|------|
| 账号一 | 2021300… | 70505 | `eyJhbGciOiJIUzUxMi…` | ✓ 有效 | 切 👁 ⧉ ⟳ ✕ |

- **用户ID** 是登录后自动从平台 `/getInfo` 取回来的，取不到就留空（不影响抢单，只影响查订单的精确度）。每一行的账号名 / 学号 / 用户ID 都能直接点开改。
- Token 默认只显示前 18 位：**👁** 看全，**⧉** 复制，**⟳** 重新校验，**✕** 删除。

### 2. 再加账号二、账号三……
还是用同一个「方式一」，**换个学号再登一次**即可：
- 学号没在库里 → **追加一行**（自动叫「账号二」「账号三」……）；
- 学号已经在库里 → **原地更新那一行的 token**（token 过期了就这么续）。

右侧页签区点 **＋ 新账号** 可以先占一个空行，再去登录会填进这一行。

### 2.5 token 失效了怎么办：🔄 重新获取
账号表每一行的操作列末尾有个 **🔄**，就是「给这个账号重新拿一个 token」：

- 这个账号**勾过「信任此设备」**（状态列显示「信任已存」）→ 点一下就完事，
  浏览器会自己跳过去，什么都不用点；
- 这个账号**还没有浏览器档案** → 会弹个小窗让你补一次门户密码，
  登录成功后记得勾「信任此设备」，以后就是全自动了。

账号表下面还有 **🔄 批量重新获取 token**，默认只处理「失效 / 未校验 / 还没 token」
的账号，逐个自动跑一遍；旁边的 **⟳ 批量校验** 是只体检、不重取。

### 3. 切换账号
右侧 **「账号页签」** 就像浏览器标签页：

```
 ● 账号一   ● 账号二   ● 账号三   ＋ 新账号
```

- 页签上的**小圆点**是该账号 token 的健康灯：灰=没登录 / 绿=有效 / 红=失效；
- 点哪个页签，下面的 **时间窗口 + 场地优先顺序 + 候选排序策略** 就换成那个账号自己的；
- 每个账号的窗口和场地顺序**互相独立**，切页即切换；
- 页签上的 **×** 删除该账号（只删它一个，不影响别人）；
- 时间窗口旁边有个 **↓ 套用到全部账号**，想给所有人统一窗口时一键搞定。

## 二点五、多因子认证（MFA）与「信任此设备」

> 这版专门修了 V3.1 的一个痛点：**每次登录都要重新过一遍企业微信验证。**

**原因**：以前每次都开一个全新的浏览器上下文，关掉浏览器 cookie 就没了，
CAS 的「信任此设备」勾了也白勾。

**V4.0 的做法**：给**每个账号**一个固定的浏览器档案目录，位置在
`config.json` 同级的 **`.profiles\<账号id>\`**。
你在这个浏览器里勾过的「信任此设备」和登录会话会**一直留在磁盘上**，跨次复用。

| 次数 | 会发生什么 |
|------|-----------|
| 第 1 次 | 打开浏览器 → 自动填好学号密码 → 你过一次 MFA（**记得勾「信任此设备」**） |
| 之后 | 同一个学号再登录 → 直接用档案里的信任记录，**几秒内自动拿到 token，什么都不用点** |

界面上能看出来：
- 账号表「状态」列多一个 **信任已存** 徽章 = 该账号的档案已在；
- 登录框下面一行提示当前账号是「档案已保存」还是「还没有档案」；
- **🧹 清除本账号的设备信任**：换电脑、或想换一个微信号验证时点它，
  只清这一个账号的档案，不影响别人。

> 说明：能不能免验证取决于 CAS 是否下发了**持久** cookie（「信任此设备」本来就是）。
> 如果哪天它改成了会话级 cookie，那就还是每次要过一遍 —— 但档案本身不会丢，
> 至少学号密码还是自动填的。

## 三、执行

| 选项 | 含义 |
|------|------|
| 只用当前标签页的账号 | 只用页签里选中的那一个号抢 |
| 全部账号**并行**开抢 | **所有账号在同一时刻各自开火**，各用各的 token / 时间窗口 / 场地顺序 |

选「全部账号并行」时，下面会多出一个「抢到之后」的选择：

| 抢到之后 | 含义 | 什么时候用 |
|---|---|---|
| **抢到一个就全体停手**（默认） | 任何一个号抢到，立刻通知其他账号收手 | 各账号抢的是**同一个时间段**，不想占下多个场 |
| 各抢各的，互不影响 | 谁抢到都继续，其他账号照抢 | 各账号抢的是**不同时间段**，本来就想各订各的 |

- 某个号的 token 失效会**自动跳过**它，不会拖累其他账号；
- 定时抢、立即抢、预览空场、接口测速、有效性检测都照旧，只是多了一层账号选择。

### 为什么能真并行

每个账号在开抢前会用 `account_params()` 合成**自己的一份参数**
（token、时间窗口、场地优先顺序都是那个账号自己的），线程之间不共享任何可变对象；
`booker.run_booking` 也不写配置、不写文件，只是纯读 + 发 HTTP 请求；
写日志的 `append_log` 内部有锁，多线程同时写不会串。

实测（假网络，两个账号各模拟 1.2 秒的抢单流程）：

| | 结果 |
|---|---|
| 两个账号进入时刻之差 | **0 ms**（同时开火） |
| 总耗时 | 1.20 s ＝ 单个账号耗时（串行会是 2.4 s） |
| token / 时间窗口 / 场地顺序 | 各自独立，无串号 |
| 抢到即停 | 账号一 0.4 s 抢到 → 账号二 0.8 s 收到信号主动退出 |

⚠️ 多账号并行时，**下单请求的总速率会翻倍**（每个账号各自约 6.7 次/秒）。
如果多个账号抢**同一个场地**，更容易触发服务端限流；
抢不同场地则基本无影响（不同目标不打同一个限流桶）。

## 五、文件都放在哪

> **V4.1 已从 V4.0 目录独立出来**，现在是桌面 `Tennis\` 下的两个平级文件夹：
>
> ```
> Tennis\
> ├─ Tennis Booking V4.0\   ← 老版本，只保留 V4.0 的 exe 与代码（含 .git 仓库）
> └─ Tennis Booking V4.1\   ← 当前版本，在这边改代码、打包
> ```
>
> 两个文件夹**各自带一份** `config.json` 和 `.profiles\`，都能直接双击跑，互不干扰。
> **改代码请认准 `Tennis Booking V4.1\`** —— V4.0 那份源码是历史快照，不再更新。

```
Tennis Booking V4.1\
├─ dist\HainanU_Tennis_Booking_V4_1.exe   ← 打包产物
├─ config.json                            ← exe 同目录自动生成（账号库 + 全部设置）
└─ .profiles\                             ← 每个账号一个浏览器档案（信任此设备存这里）
    ├─ acc1\
    └─ acc2\
```

- **打包成 exe 后**：`config.json` 生成在 **exe 的同目录**。exe 放桌面，配置就在桌面，
  下次双击还是读同一个 —— 改了配置不会丢。
- **源码模式**（`python src\app_server.py`）：配置落在 `src\config.json`。
- 想把一套配置搬到另一台电脑：把 `config.json` 和 `.profiles\` 一起拷走即可；
  只想搬账号不想留设备信任，就只拷 `config.json`。

## 五点五、打包成 exe & 「浏览器模块不可用」

### 打包

```
双击 build.bat（约 1-2 分钟）
产物：dist\HainanU_Tennis_Booking_V4_1.exe（约 52 MB）
```

`build.bat` 会自动挑一个装了 `playwright` + `PyInstaller` 的解释器，先跑一遍自检再打包。
**注意**：必须在**项目根目录**执行，`--add-data` 写 `src/index.html;.`，入口写 `src/app_server.py`；
跑到 `src\` 里再打包会报 `Unable to find ... index.html`。

### 内置浏览器（bundled_chromium）怎么来

仓库里**不带**浏览器（约 430MB，放不进 GitHub）。需要给别人做一个「双击就能用」的包时，
先自己下一份放到项目根：

```bat
set PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright
playwright install chromium
```

（直连官方 CDN 基本下不动，用上面这个国内镜像几秒就好。）

然后把下载下来的 `chrome-win64` 整个文件夹拷成项目里的 `bundled_chromium\chrome-win64\`：

```
Tennis Booking V4.1\
├─ HainanU_Tennis_Booking_V4_1.exe
└─ bundled_chromium\chrome-win64\chrome.exe     ← 必须和 exe 同一层
```

**exe 和 bundled_chromium 必须放在同一个文件夹里**，分开就打不开浏览器了。

打出来的 exe **自带 Playwright 和浏览器驱动**，所以：

> **「浏览器模块不可用」这个问题在 exe 里不存在** —— 打包版不需要本机装 Python 或 playwright，
> 也不依赖 PATH 上那个 python 是谁。只要有 Edge（或 Chrome）就能用。

把 exe 单独拷到桌面双击就能跑，`config.json` 和 `.profiles\` 会生成在 exe 旁边。

### 打成「一个压缩包发出去」

`build.bat` 最后一步会调用 `过程文件\make_release_zip_lzma_v41.py`，生成：

```
HainanU_Tennis_Booking_V4_1_Windows_x64.zip
└─ HainanU_Tennis_Booking_V4_1\
   ├─ HainanU_Tennis_Booking_V4_1.exe
   ├─ bundled_chromium\chrome-win64\
   ├─ 使用前必读.txt
   └─ README.md
```

几个要点：

- **压缩方式用的是 LZMA**（不是普通 deflate）。同样是 `.zip` 扩展名，
  接收方右键「全部解压缩」或双击就能打开，**不用装任何额外软件**。
  实测内置 Chromium 的 `chrome.dll`：301 MB → 96 MB（deflate 只能压到 148 MB）。
  代价是打包要跑 15-20 分钟（解压只要 10 秒左右）。
- **包里不含 `config.json` 和 `.profiles\`** —— 那是本机的 token、密码和设备信任档案，
  发给别人前一定要排除。脚本里的 `SKIP_FILES` / `SKIP_DIRS` 已经处理好了，
  并且压缩完会做一次**私密数据自检**再报 SHA256。
- 打包前先把要发的内容放进 `release_zip\HainanU_Tennis_Booking_V4_1\`（exe + bundled_chromium + 文档）。
  这一步由 `过程文件\prepare_v41_release.py` 自动摆好。
- 只想更新本机 exe、不需要分包时，`build.bat` 跑到第 4 步按 Ctrl+C 中断即可。

### 验证打包出来的 exe 是不是新代码

**别在 exe 二进制里搜字符串** —— PyInstaller 把 `.pyc` 压缩了，搜不到。
正确做法是把 exe 真跑起来，打 HTTP 接口断言行为：

```
python 过程文件\verify_v41_exe.py
```

它会自动起 exe、开浏览器端口、检查页面里有没有「挂机过夜」卡片和 6 个新控件 id、
往 `/api/accounts/password` 存一个测试密码、回读 `config.json` 确认盘上是 `v1:` 混淆串
而不是明文、确认 `/api/accounts` 不下发密码串，最后 `/api/refresh` 能正常响应。

### 源码模式下如果显示「浏览器模块不可用」

面板上的诊断会直接告诉你三件事：当前用的是哪个 python、playwright 装没装、找到了哪些浏览器。

常见原因是**本机有多个 python，PATH 上那个没装 playwright**（比如托管环境的 python 装了，
系统 python 没装），程序却正好捡到了没装的那个。三种解法，任选：

1. **点面板上的「🛠 一键安装 Playwright」** —— 自动给当前解释器装上（需要联网）；
2. 手动装：`python -m pip install playwright`，然后用**同一个** python 启动 `src\app_server.py`；
3. **直接用打包好的 exe** —— 最省事，环境依赖全部内置。

浏览器要求：Microsoft Edge 或 Google Chrome 任一（Windows 自带 Edge，一般不用管）。

## 五点八、登录流程（「方式一」一律弹浏览器）

「🔑 登录并获取 token」点下去**一定会弹出一个真实浏览器窗口**（Edge/Chrome），和 V3 的体验一致：在浏览器里输密码、过 MFA（企业微信 / 短信 / 扫码由你自己完成），token 由浏览器内实时捕获后写回账号库。工具**不绕过 MFA**。

> 早期版本（V4.0 某次迭代）曾改成「先偷偷走服务端 CAS、只有检测到 MFA 才补开浏览器」，
> 结果对部分账号误判成「登录成功、不开浏览器」，导致点了登录没反应。
> 现改回**一律用浏览器完成登录**：无论账号是否开了多因子认证，浏览器都会弹出来，
> MFA 自然地在浏览器里由本人完成。

内部逻辑（`app_server.py` 的 `/api/caslogin`）：
- 账号已有浏览器档案且标记过 MFA → 直接进入那份档案（多半靠「信任此设备」免验证直接拿到 token，浏览器照样弹）；
- 浏览器模块可用 → 一律 `spawn browser_login` 开浏览器完成登录；
- 浏览器模块不可用（源码模式没装 Playwright 的极端情况）→ 退回服务端 CAS 兜底拿 token。

`browserlogin.py` 的 MFA 兜底判定（用于识别内嵌页 / 挂起态）仍保留：
- 跳转 URL 含 `reAuth / multifactor / mfa / otp / factor / 企业微信 / 短信验证 / 扫码 …`；
- 某一跳的**响应体**出现上述标记（200 内嵌页）；
- 拿到了 token 但**校验没过**（疑似 MFA 挂起）→ 同样在浏览器里补全。

## 六、数据安全

- **密码不保存**，只在登录那一次请求里用；
- **token 保存在 `config.json`**（程序目录下），等同于账号密码，别把整个目录发给别人前忘了删它；
- 表格里的 token 默认只显示前 18 位；
- 前端整包保存配置时有双重保护：**不会把 token 抹掉**，也**不会因为少传一个账号就把它删掉**（删号必须走专门的删除按钮）。
